## Security and authorization evidence

The [inventory](v0.2.1-audit-evidence/authorization-coverage.md) expands route
registration loops: 121 REST method/path patterns, one ALL `/mcp` transport and
30 tools in the audited release. All 44 can actions appear in table-driven rule
matrices. Core business methods use requireMember → can; public health,
auth-method discovery and authentication/session establishment are intentional
provider/transport exceptions. Initialize/list discovery likewise has no domain
mutation. A07/A08 state the remaining literal/coverage gaps explicitly.

  bytes and only hash persisted; revocation checked again on actor load.
  `packages/core/src/index.ts:157`, `:173`, `:874`, `:1014`, `:323`. DTO excludes
  hash (`:140`); pino redacts authorization/cookies/token (`apps/api/src/logger.ts:8`).
  No raw-token log path found. MCP diagnostic logs use bounded identifiers and
  error names (`apps/api/src/mcp.ts:93`, `:420`).
- CRM phone/email uses contact:details redaction and grant/policy capability
  checks; unavailable fields are excluded from search matching.
  `packages/core/src/crm.ts:84`, `:133`, `:409`, `:981`;
  `permissions.ts:149`. Default crm.read is ask and contact-details deny; an
  explicit admin allow policy is also an authorized capability, so an expiring
  grant is not the only permitted mechanism. Relation graph selects no phone or
  email (`relations.ts:143`). Finance is person-admin only (`permissions.ts:123`;
  `timeline.ts:850`, `:872`) across direct operations and projections.
- SQL values are parameter bound (`crm.ts:106`); no production eval/unsafe SQL

  schemas and adapter tests (`apps/api/src/app.test.ts:585`). Inline boot script
  uses controlled locale/build state (`apps/web/app/layout.tsx:94`).
- CORS is exactly URL(AUTH_URL).origin, foreign-origin mutations and WebSockets

  follows AUTH_URL (`packages/core/src/index.ts:262`). Missing Origin remains
