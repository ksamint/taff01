## Original-agent approved operations (implementation, unverified)

- POST /api/approved-operations and POST /api/approved-operations/status require the ORIGINAL connector agent bearer token plus x-taff-approval-signature. The status route never executes a mutation; 404 is only absence at read time, not proof a delayed request will never arrive.
- Envelope: version=1, audience=taff_agent, issuer=twin, source=private_wechat, receipt_id UUID, controller_id, workspace_id UUID, expires_at ISO UTC, tool, arguments (original MCP arguments), expected_version (positive integer or null for task creation), credential_hash SHA256(raw original token), operation_hash. HMAC/hash canonicalization and key match the review protocol. Bind the immutable envelope at first dispatch; reconciliation must reuse it.
- Supported: tasks.create (expected_version=null); tasks.edit, calendar.set (task version and args.version); tasks.comments.add, runs.start (task version as expected_version); runs.control, runs.event, files.attach, runs.submit (run version and args.version). Read the version using tasks.list exact task ID or runs.get. Legacy unversioned tools and tools outside this list remain unsupported.
- The current original token is reauthenticated, workspace constrained and checked for revocation inside the transaction. Existing core operations still enforce their original scopes/capabilities/resource permissions. Task/run version validation and the actual existing mutation share row locks and a transaction with the receipt insert. No mapped-human impersonation or permission widening occurs.
