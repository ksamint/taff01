## Item 1: flaky live checks

### Mind map: `mind.spec.ts:66` (keyboard) and `:220` (evidence)

**Cause: an app race, not a test race.** After a write, the cached row kept
its old `version` until the follow-up refetch arrived. A source that had
just been created also kept its temporary `optimistic:N` id until then.
Writes could also run concurrently. A version-checked action taken in that
gap failed:

- **Archive right after Undo of a node edit** sent version 2 while the
  server had 3. The server answered 409, and the toast said "This changed
  elsewhere". This is the keyboard test.
- **Editing a just-created source** sent its temporary id. The server
  answered 400, and the toast said "Check the details and try again". This
  is the evidence test.

Playwright reports the test declaration as the failure location, which is
why the deploy report shows `:66` and `:220`.

**Evidence** (local production build, `--repeat-each`, logs in the build
session's scratchpad, not committed):

| Run | Result |
| --- | --- |
| `main`, no added latency, 3 locales × 3 | 27/27 pass (not reproduced) |
| `main`, 150 ms added browser latency, × 5 | 24/30 fail with the 409/400 above (keyboard 15/15, evidence 9/15) |
| First fix only (write the saved row into the cache) | evidence fixed; keyboard still 12/15 failing (Archive while Undo in flight) |
| Final fix, 150 ms latency | 45/45 pass |
| New regression spec against `main`, no latency, × 2 | 9/12 fail (it forces the race) |

**Fix (on this branch):**

- **`apps/web/src/lib/mutations/mind.ts`**
  - Every successful write and every undo puts the server's returned row
    straight into both cached maps.
  - Mind-map writes run one at a time.
  - Each write sends the version the person acted on, advanced only past
    this tab's own later writes to that row (`sendVersion` /
    `recordOwnWrite`). Other people's changes are never skipped, so real
    conflicts still return 409.
- **`apps/web/src/components/mind-view.tsx`** (about line 890): a source's
  Edit button is disabled while the row is still optimistic. Its Archive
  button already was.
- **Tests:**
  - `apps/web/src/lib/mutations/mind.test.ts` (new unit tests).
  - New regression tests in `e2e/mind.spec.ts`. They hold the map refetch
    with `holdRequest`, which is never unrouted, so the race happens every
    time.
  - No assertion or timeout was loosened.

**Not yet verified:** the new spec has not been run against the final fixed
build without added latency. Rebuild first, because the build agent's local
production build was left on `main`'s mind-map code.

### Restricted-member check: `platform.spec.ts:28`

**Most likely cause, from the code.** This is not confirmed against the live
harness, which is not in the repo.

- When a page's realtime socket first opens, `apps/web/src/lib/realtime.ts`
  only marked queries stale; it did not refetch them.
- The server closes existing sockets when a membership role changes.
- So a role change made between the page's first data load and its socket
  opening never reached that page. `me` and the permissions stayed out of
  date, and admin-only finance stayed shown or hidden wrongly until the
  window was refocused.

**Fix:**

- **Change:** the first socket open now also refetches `/api/me`, one extra
  request per connection. If the role is unchanged, nothing else happens. If
  it changed, the cached data is cleared and every query reloads with the
  right permissions.
- **Tests:**
  - `apps/web/src/lib/realtime.test.ts`: call counts are updated and one
    test is added.
  - `e2e/finance-visibility.spec.ts` is new. An admin sets a contract
    amount, and a verified second person joins as a member. It then checks
    that:
    - the API returns no finance figures to the member, only delivery %;
    - the timeline shows no figures;
    - a promotion made while the member's socket is held back shows the
      figures once the socket opens;
    - a demotion over the live socket removes them.
- **Result:** 6/6 fail without the fix; 3/3 pass with it.

## Item 3: M14 notes (done, PR #26)

- **Demo email unverified.**
  - `packages/core/src/seed.ts` marks seeded demo accounts' email as
    verified. It is idempotent, runs under the seed lock and is audited.
    Passwords and accounts are untouched, and no migration is involved.
  - Covered by `prototype-seed.integration.test.ts`.
  - As a result, `e2e/release/support.ts` now runs the invite step instead of
    skipping it.
- **Digest radio needed a retry.**
  - **Cause:** every notification control was disabled while any save was in
    flight, so a second click was lost.
  - **Fix:** a latest-wins writer (`apps/web/src/lib/notification-queries.ts`)
    keeps one save in flight and sends the latest choice next with the
    returned version. The controls stay enabled.
  - **Tests:** unit tests, plus an e2e that holds the first PATCH
    (`e2e/notifications.spec.ts`).
  - **Changed assertion:** the old assertion that `notification-review` was
    disabled during a held save checked the bug itself. The new one checks
    that the controls stay usable and that both values roll back on
    rejection.
- **Phone status showed "done" early.** The phone status picker
  (`task-editor.tsx`) now uses `useUndoableTaskEdit`, like desktop:
  - optimistic, sends `version`;
  - on error, rolls back with an alert;
  - on success, shows a toast with 撤銷.

  Covered by `cache-updates.test.ts` and `e2e/optimistic-m4.spec.ts`.
