# Local wire replay

R0.5 records which Node REST routes and MCP tools the existing suites
exercise, and compares supported reads against a second loopback endpoint.
It keeps recordings in the ignored `.taff-replay/<run>/` folder. Each new
run name is exclusive. Use disposable local services and synthetic fixtures.

## Capture

```sh
pnpm replay capture wave0-unit -- pnpm test
pnpm replay capture wave0-browser -- pnpm e2e
```

For MCP, start a fresh local Node API in one terminal and run the existing
smoke script against that API from another terminal.

```sh
pnpm replay capture wave0-mcp -- pnpm --filter @taff/api dev
pnpm mcp:smoke
```

The preload must be present in the API process itself. Browser tests that
reuse an already running, uninstrumented API cannot be captured. In-process
Hono requests in Vitest and HTTP traffic to the instrumented dev server use
the same observer. It does not run in production mode. The web browser,
database engine and other services have no recorder. Use existing test
setup for any dependency the suite needs.

The observer records registered route templates, HTTP status, and known MCP
method and tool identifiers. It never writes raw request URLs, query
values, headers, cookie or bearer contents, or unapproved request and
response values. For an explicitly supported read, it projects the response
onto the fixed fields in `wire.mts`. Unknown bodies, arbitrary free text,
and credential-exchanging endpoints are recorded as metadata only.
Only use recordings generated by this observer.

## Compare

```sh
pnpm replay compare wave0-unit http://127.0.0.1:3001
pnpm replay compare wave0-browser http://127.0.0.1:3003 health,authMethods
```

The optional final argument selects recipes by comma-separated name. Use
the same synthetic fixture state on both sides. Set
`TAFF_REPLAY_SESSION_COOKIE` to a fresh runtime
`better-auth.session_token=...` cookie pair to compare notification
preferences, or set `TAFF_REPLAY_AGENT_TOKEN` to a fresh local agent
credential for catalog discovery. The comparator uses them only as request
headers. No credentials need to be written to disk or supplied as command
arguments. A missing credential skips the corresponding recipe and reports
why. The CLI exits nonzero on any mismatch or an empty comparison.

| Recipe | Compared response |
| --- | --- |
| `health` | Health status |
| `authMethods` | SMS availability |
| `oauthServer`, `oauthResource`, `oauthMcpResource` | Public discovery metadata and scopes |
| `notifications` | The signed-in test person's notification preferences |
| `mcpCatalog` | The 2026-07-28 catalog tool names, boolean annotations and cache controls |

An authenticated catalog read can write the Node API's normal local audit
record. Run it only against a disposable local target or a test double with
the audit sink replaced. No business mutations or MCP tool calls are replayed.

Objects compare in sorted key order. Arrays keep their order. RFC 3339
offsets are converted to UTC without losing fractional precision. Reported
differences name JSON Pointers and do not print values.

| Exact allowance | Treatment |
| --- | --- |
| OAuth discovery URL fields for issuer, resource, authorization servers and named endpoints | A credential-free loopback origin can change. Paths still compare exactly. Query strings and fragments are outside the recipe. |
| Modern MCP catalog response `/body/id` | A valid JSON-RPC ID is replaced with a marker. Presence still compares. |
| Modern MCP catalog response `/body/result/_meta/io.modelcontextprotocol~1serverInfo` | Presence and object type compare. Free-text server identity values are excluded. |

There is no global skip for IDs, dates or keys named token. Dynamic task,
project or workspace IDs need a verified fixture mapping before those routes
can be replayed. Tests that mutate tasks, approvals, roles, sessions, or
tokens can establish side effects that a clean target cannot reconstruct.
Those cases, legacy MCP sessions, resource streams, image bodies and
WebSockets are outside the first replay set. The report separates registered,
observed and actually replayed routes and tools, using the generated Node
REST and MCP registries. A catalog read does not count as replay of any tool.
Zero diffs on the initial recipes do not establish parity for an unmapped
family or authorize switching it to Rust.

Run the focused self-check with `pnpm test scripts/replay/replay.test.ts`.
It starts a real loopback Node Hono adapter with a synthetic core, verifies
four unchanged REST reads and the MCP catalog with a fresh fixture token.
It changes one response field to prove
that only its route and JSON pointer are reported.
